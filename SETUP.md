# Bite & Beans — setup guide

This project is now a Next.js 16 app with a Supabase-backed content studio at `/admin`.

- Public pages: `/`, `/menu`, `/experience`, `/visit`
- Admin: `/admin` (sign in at `/admin/login`)
- Database: Supabase Postgres
- Images: Supabase Storage bucket `site-media` (public read, admin-only uploads)

Until Supabase is configured, the public site renders the bundled content in
`data/content.json`. The admin requires Supabase.

---

## 1. Requirements

- **Node.js 20.9 or newer** (recommended; the production build is verified with Node).
- A Supabase project (free tier is fine).

> **Use npm for this project.** Bun can stay installed for other tools, but avoid
> `bun install`: it recreates Bun `.exe` shims in `node_modules/.bin`, which can
> make Next run under Bun. Next 16's production build currently crashes inside
> Bun's CommonJS loader (`Expected CommonJS module to have a function wrapper`).
> Use `npm install` / `npm ci`, `npm run dev`, and `npm run build`.

## 2. Install

```bash
npm install
# or: bun install
```

## 3. Create the database

In the Supabase dashboard:

1. Create a project.
2. Open **SQL Editor → New query**.
3. Paste the entire contents of **`supabase/setup.sql`**.
4. Press **Ctrl+A** to select everything, then click **Run**.
5. Wait for **“Success. No rows returned”**.

`setup.sql` is the schema plus the seed in one file, generated by
`npm run setup:generate`. Using it avoids the most common mistake: running the
seed before all schema tables exist, or running the two files in different
projects/branches.

If you prefer to run them separately, run `supabase/schema.sql` first, then
`supabase/seed.sql`, in the **same** project and the **same** database branch.

Afterwards, run `supabase/verify.sql` to confirm every table exists and to see
row counts. The expected result is 11 tables marked `OK`.

## 4. Create an admin user

1. Supabase dashboard → **Authentication → Users → Add user**.
2. Enter an email and password. Enable “auto confirm” if offered.
3. Run this in the SQL Editor, replacing the email:

```sql
insert into public.admin_users (user_id, email)
select id, email
from auth.users
where email = 'you@example.com'
on conflict (user_id) do nothing;
```

Being signed in is **not** enough to edit: a user must also be listed in
`public.admin_users`. This is what the `is_admin()` function checks.

To add another admin later, repeat the Auth user + SQL steps.

## 5. Configure environment variables

Copy `.env.local.example` to `.env.local`:

```bash
NEXT_PUBLIC_SUPABASE_URL=https://your-project-ref.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=your-anon-key
```

Find both under **Project Settings → API** in Supabase.

Never put the `service_role` key in this file or anywhere in the browser app.
The public `anon` key is designed to be public; RLS protects the data.

## 6. Run it

```bash
npm run dev
```

- Public site: <http://localhost:3000>
- Admin: <http://localhost:3000/admin/login>

## 7. Verify Storage

`schema.sql` creates the `site-media` bucket and its policies. If you created the
bucket manually instead, make sure it is **public** and has these policies:

- `select` for `anon, authenticated`
- `insert`, `update`, `delete` for `authenticated` where `public.is_admin()` is true
- 10 MB file size limit
- MIME types: JPEG, PNG, WebP, GIF, AVIF

## What can be edited

| Admin page | Content |
|---|---|
| Dashboard | Counts, quick links, setup status |
| Menu | Categories, dishes, descriptions, “new” badges, and all price variants |
| Highlights | Home page “Fan Favourites” cards |
| Menu images | Menu photo carousel |
| Experience | Experience gallery, plus home page “Space” teaser selection |
| Amenities | Visit page amenities and the home feature strip |
| Add-ons | Menu extra chips and prices |
| Page copy | Headings, descriptions, and button labels |
| Site settings | Logo, hero/visit images, address, maps, hours, phone, WhatsApp, Instagram, average spend, SEO metadata, theme colour |

Every content row has:

- **Published** — hides it from the public site immediately.
- **Sort order** — lower numbers appear first.

Images can be uploaded to Supabase Storage or referenced by an existing
`/assets/...` path. The original files remain in `public/assets`.

## Data model

```
site_settings          one row (id = 1)
page_copy              key/value copy strings, grouped by page
menu_categories        id, slug, name, filter_label, icon, image_url, is_compact,
                       sort_order, is_published
menu_items             category_id, name, description, is_new, sort_order, is_published
menu_item_variants     item_id, label, price (integer rupees), sort_order
add_ons                name, price, sort_order, is_published
menu_gallery           image_url, label, sort_order, is_published
highlights             image_url, badge, category, title, description, price_label,
                       sort_order, is_published
experience_photos      image_url, title, description, is_featured_home,
                       home_title, home_description, home_sort_order, sort_order,
                       is_published
amenities              name, icon_url, show_on_home, home_sort_order, sort_order,
                       is_published
admin_users            user_id → auth.users, email
```

## Security model

- Public reads use the anon key and RLS returns **published** rows only.
- Writes require an authenticated user listed in `public.admin_users`.
- The proxy refreshes Supabase auth cookies on every `/admin` request.
- The admin layout and every Server Action re-check `is_admin()`.
- `save_menu_item()` runs as the caller (`security invoker`), so RLS still applies.
- Images are public to read; uploads require admin membership.
- `/admin` is marked `noindex`.

## Editing content locally before Supabase

`data/content.json` is the source of truth for:

1. the public fallback content, and
2. the generated SQL seed.

If you change it, regenerate the seed:

```bash
npm run seed:generate
```

Then re-run `supabase/seed.sql` in the SQL Editor.

The original static version is archived in `legacy/` for reference only.

## Deployment

The app needs a Node-capable host (Vercel, Netlify, Render, Railway, a VPS, etc.).
It cannot be exported as a purely static site because admin auth and Server Actions
need a server.

1. Push the repo to your Git host.
2. Create the project on Vercel/Netlify and set:
   - `NEXT_PUBLIC_SUPABASE_URL`
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`
3. Build command: `npm run build`; start command: `npm start`.
4. In Supabase → **Authentication → URL Configuration**, add your production URL:
   - Site URL: `https://your-domain.com`
   - Redirect URLs: `https://your-domain.com/**`
5. Visit `https://your-domain.com/admin/login` and sign in.

Next.js serves `/admin` natively; no rewrite rules are needed.

## Troubleshooting

| Symptom | Fix |
|---|---|
| Admin shows “Setup required” | `.env.local` is missing or still has placeholder values. Restart `npm run dev` after editing it. |
| “This account is not an admin” | Add the user to `public.admin_users` with the SQL above. |
| Dashboard says tables could not be read | Run the complete `supabase/setup.sql` in the SQL Editor. |
| Seed fails with `42P01: relation "public.menu_categories" does not exist` | The schema was only partially applied, or it ran in another project/branch. Run **`supabase/setup.sql`** as one query. |
| Seed fails with `syntax error at end of input` | The SQL was truncated or only a selection was run. Open a new query, paste the whole file, press **Ctrl+A**, then Run. |
| Schema/seed seems to run but data is missing | The SQL Editor project ref (in the dashboard URL) must match the ref in `NEXT_PUBLIC_SUPABASE_URL`. |
| “new row violates row-level security policy” | The signed-in user is not in `public.admin_users`, or the Storage policies were not applied. |
| Images upload but the site shows a broken image | Check the `site-media` bucket is public and the URL field contains the full public URL. |
| Public site shows old content | Content is fetched per request (`force-dynamic`). Hard-refresh; if the DB is unreachable, the site intentionally falls back to `data/content.json`. |
